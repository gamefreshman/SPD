# DPO 共享参考条件修复计划（v4）

修复 DPO 训练中 winner/loser 使用各自 x3/x4 而非共享参考 NP 条件的语义偏差，确保 DPO loss 正确比较 `p(winner_x1 | ref_x3x4)` vs `p(loser_x1 | ref_x3x4)`。

---

## 1. 问题分析

### 模型架构验证

Shepherd `Model.forward()` 流程（`model.py:1689-1722`）：

```
x1_encoder → x3_encoder → x4_encoder
       ↓           ↓           ↓
  heterogeneous_graph_encoder (跨模态空间交叉注意力)
       ↓           ↓           ↓
  joint_processing (全局 l=1 embedding 聚合，所有模态的时间步拼接)
       ↓           ↓           ↓
  x1_denoiser   x3_denoiser   x4_denoiser
```

x3/x4 信息通过两个通道流入 x1 去噪：
1. **heterogeneous graph encoder**：x1/x3/x4 节点在共享 3D 空间中通过 radius graph 交叉传信息
2. **joint processing**：所有模态的全局 l=1 embedding 和时间步 embedding 拼接后残差更新到 x1 节点

x1 的去噪输出 `pos_out`, `x_out`, `bond_edge_x_out` **直接依赖于输入的 x3/x4 数据**。

### 当前问题

| 阶段 | winner 的 x3/x4 | loser 的 x3/x4 |
|------|-----------------|-----------------|
| 采样 | 参考 NP（inpaint） | 参考 NP（inpaint） |
| 打分 | 参考 NP（对比评分） | 参考 NP（对比评分） |
| **训练** | **winner 自己的** | **loser 自己的** |

训练时 DPO loss 实际比较的是：
```
MSE(model(winner_x1 | winner_x3x4), noise_w)  vs  MSE(model(loser_x1 | loser_x3x4), noise_l)
```

而正确语义应该是：
```
MSE(model(winner_x1 | ref_x3x4), noise_w)  vs  MSE(model(loser_x1 | ref_x3x4), noise_l)
```

**信号被稀释**：模型学到的是"谁在自己的条件下更自洽"，而非"在同一参考条件下，谁更值得偏好"。

### 隐蔽 bug：共享 seed 也无法保证 x3/x4 一致

当前 `dpo_dataset.py:91` 用 `_temporary_numpy_seed(seed)` 后依次构造 x1→x3→x4。RNG 消费链：

```
get_x1_data():
  randn(num_atoms+VN, 3)          ← pos_noise，取决于 num_atoms
  randn(num_atoms+VN, atom_ch)    ← x_noise
  randn(num_bonds, bond_ch)       ← bond_noise
get_x2_data() for x3:
  randn(num_surf_pts+VN, 3)       ← surface pos_noise
get_x3_data_electrostatics_only():
  randn(num_surf_pts+VN, 1)       ← ESP x_noise
get_x4_data():
  randn(...)                       ← pharm noise (多次)
```

winner 15 原子 vs loser 20 原子 → x1 阶段消费的随机数量不同 → 即使 seed 相同，x3/x4 噪声也不一致。

### 修复后的连锁影响

- **x1 DPO loss**：正确。winner/loser 的 x1 不同，在相同条件下比较。
- **x3/x4 DPO loss**：**应该禁用**。winner/loser 的 x3/x4 输入和 GT noise 完全相同（同一参考 NP），虽然模型预测会因 x1 不同而不同（通过 heterogeneous graph），但这个信号语义不清。
- **standard denoising loss**：第一阶段不改（见 §2.5）。

## 2. 修改计划

### 2.1 `DPODataset` — 共享参考条件 + reference cache

**文件**: `Shepherd/src/shepherd/dpo_dataset.py`

**a) 新增 reference cache**

```python
class DPODataset(Dataset):
    def __init__(self, ..., reference_cache=None):
        self.reference_cache = reference_cache or {}
        # reference_cache: Dict[int, {
        #     'mol': Chem.Mol,                # 居中后的参考分子
        #     'charges': np.ndarray,
        #     'radii': np.ndarray,
        #     'mol_coordinates': np.ndarray,   # 居中后坐标
        # }]
```

`reference_cache` 由 `dpo_train.py` 构建并传入，DPODataset 只读使用。PreferencePairBuilder 不持有也不构建 cache。

**b) 偏好对格式**

当前：`(winner_mol, loser_mol, score_w, score_l)`
新：`(winner_mol, loser_mol, reference_idx, score_w, score_l)`

每个 pair 只存一个 `reference_idx`（int），通过 `self.reference_cache[reference_idx]` 获取参考分子数据。

**c) 新增纯 reference 输入的 helper：`_build_x3_from_ref()` 和 `_build_x4_from_ref()`**

**不能复用**当前的 `_build_x3()` 和 `_build_x4()`。原因：

当前 `_build_x3()`（`dpo_dataset.py:212`）签名：
```python
def _build_x3(self, mol_coordinates, radii, charges,
              x1_pos, x1_virtual_node_mask, t_idx, ts_x1, t_x1):
```
当 `x1_pos is not None` 时，它用 `x1_pos[~x1_virtual_node_mask]` 作为 `atom_centers` 来生成分子表面。这意味着表面点云的空间位置**依赖于候选分子的 x1 原子坐标**（含 virtual node 和加噪后的位置）。`_build_x4()` 同理。

虽然传 `x1_pos=None` 会 fallback 到 `mol_coordinates`，但这种隐式 fallback 语义不清且脆弱。新增专用 helper：

```python
def _build_x3_from_ref(self, ref_mol_coordinates, ref_radii, ref_charges, x3_schedule):
    """从参考 NP 构造 x3 数据，不依赖任何 x1 信息。
    atom_centers 直接用 ref_mol_coordinates（参考分子的居中原子坐标）。
    接收已解析的 schedule dict，不做时间步推导。
    """
    atom_centers = ref_mol_coordinates
    virtual_node_pos = (
        atom_centers.mean(0)[None, ...]
        if self.base_dataset.add_virtual_node_x3 and not self.base_dataset.recenter_x3
        else None
    )
    x3_data, x3_pos, x3_vmask = self.base_dataset.get_x2_data(
        ref_radii, atom_centers,
        self.base_dataset.num_points_x3,
        self.base_dataset.recenter_x3,
        self.base_dataset.add_virtual_node_x3,
        self.base_dataset.remove_noise_COM_x3,
        x3_schedule["t"], x3_schedule["alpha_dash_t"], x3_schedule["sigma_dash_t"],
        virtual_node_pos=virtual_node_pos,
    )
    x3_com_displacement = (x3_data["com"] - x3_data["com_before_centering"]).detach().cpu().numpy()
    charge_centers = atom_centers + x3_com_displacement
    x3_data = self.base_dataset.get_x3_data_electrostatics_only(
        ref_charges, charge_centers, x3_data, x3_pos, x3_vmask,
        x3_schedule["t"], x3_schedule["alpha_dash_t"], x3_schedule["sigma_dash_t"],
    )
    return self._attach_schedule_tensors(x3_data, x3_schedule)

def _build_x4_from_ref(self, ref_mol, ref_mol_coordinates, x4_schedule):
    """从参考 NP 构造 x4 数据，不依赖任何 x1 信息。"""
    atom_centers = ref_mol_coordinates
    virtual_node_pos = (
        atom_centers.mean(0)[None, ...]
        if self.base_dataset.add_virtual_node_x4 and not self.base_dataset.recenter_x4
        else None
    )
    x4_data = self.base_dataset.get_x4_data(
        ref_mol,
        self.base_dataset.recenter_x4,
        self.base_dataset.add_virtual_node_x4,
        self.base_dataset.remove_noise_COM_x4,
        x4_schedule["t"], x4_schedule["alpha_dash_t"], x4_schedule["sigma_dash_t"],
        virtual_node_pos,
    )
    return self._attach_schedule_tensors(x4_data, x4_schedule)
```

**时间步处理策略（定死）**：在 `get()` 中先统一解析所有 schedule，再把 resolved schedule dict 传入 helper。不在 helper 内部做时间步推导。

```python
# get() 中：
x1_schedule = self._schedule_params("x1", t_idx)
ts_x1 = self.noise_schedule_dict["x1"]["ts"]
t_x1 = x1_schedule["t"]
x3_schedule = self._resolve_timestep("x3", t_idx, ts_x1, t_x1)
x4_schedule = self._resolve_timestep("x4", t_idx, ts_x1, t_x1)
```

> **注意**：`_resolve_timestep()` 当前签名需要 `ts_x1`（完整时间步序列）和 `t_x1`（当前时间步值）。`get()` 中需要从 `self.noise_schedule_dict["x1"]["ts"]` 获取 `ts_x1`，从 `x1_schedule["t"]` 获取 `t_x1`。

**d) 重写 `get()` 方法**

返回格式必须与当前 `collate_dpo_batch()` 接口一致：返回 **dict**，包含 `"winner"`, `"loser"`, `"shared_timestep"`，可选 `"winner_score"`, `"loser_score"`。

```python
def get(self, idx):
    winner_mol, loser_mol, reference_idx, *score_payload = self.preference_pairs[idx]
    ref = self.reference_cache[reference_idx]

    # 1. 采样共享时间步
    schedule_key = "x1" if "x1" in self.noise_schedule_dict else next(iter(self.noise_schedule_dict))
    ts = self.noise_schedule_dict[schedule_key]["ts"]
    t_idx = int(np.random.randint(0, len(ts)))

    # 2. 统一解析所有模态的 schedule
    x1_schedule = self._schedule_params("x1", t_idx)
    ts_x1 = self.noise_schedule_dict["x1"]["ts"]
    t_x1 = x1_schedule["t"]
    x3_schedule = self._resolve_timestep("x3", t_idx, ts_x1, t_x1)
    x4_schedule = self._resolve_timestep("x4", t_idx, ts_x1, t_x1)

    # 3. 构造一次共享 x3/x4（纯 reference helper，无 x1 依赖）
    shared_x3 = self._build_x3_from_ref(ref['mol_coordinates'], ref['radii'], ref['charges'], x3_schedule)
    shared_x4 = self._build_x4_from_ref(ref['mol'], ref['mol_coordinates'], x4_schedule)

    # 4. deepcopy 给 winner 和 loser（避免 tensor aliasing）
    winner_x3, winner_x4 = deepcopy(shared_x3), deepcopy(shared_x4)
    loser_x3, loser_x4 = deepcopy(shared_x3), deepcopy(shared_x4)

    # 5. x1 各自独立构造（不同分子，独立噪声，共享 t_idx）
    winner_x1, _, _ = self._build_x1(winner_mol, t_idx)
    loser_x1, _, _ = self._build_x1(loser_mol, t_idx)

    # 6. 组装 HeteroData
    winner_data = self._to_heterodata({
        "molecule_id": torch.tensor([idx * 2], dtype=torch.long),
        "x1": winner_x1, "x3": winner_x3, "x4": winner_x4,
    })
    loser_data = self._to_heterodata({
        "molecule_id": torch.tensor([idx * 2 + 1], dtype=torch.long),
        "x1": loser_x1, "x3": loser_x3, "x4": loser_x4,
    })

    # 7. 返回 dict（与 collate_dpo_batch() 接口一致）
    shared_timestep = torch.tensor([t_x1], dtype=torch.float32)
    batch = {
        "batch_type": "dpo",
        "winner": winner_data,
        "loser": loser_data,
        "shared_timestep": shared_timestep,
    }
    if len(score_payload) >= 2:
        batch["winner_score"] = score_payload[0]
        batch["loser_score"] = score_payload[1]
    return batch
```

关键约束：
- x1 噪声**不需要**共享（winner/loser 是不同分子，噪声独立是正确的）
- 必须共享的是 **t_idx** 和 **ref x3/x4 数据（含噪声）**
- `deepcopy` 确保无 tensor aliasing
- 返回 dict 格式与 `collate_dpo_batch()` 完全一致

**e) 位置对齐**

保持与推理一致的 centering 约定：各模态各自居中到自己的 COM，不额外做对齐变换。x1 居中到候选分子的 COM，x3/x4 居中到参考 NP 的 COM。模型通过跨模态边的相对距离传递信息，这与推理时的行为一致。

### 2.2 `PreferencePairBuilder` — 输出 reference_idx + 修复 pair_key

**文件**: `Shepherd/src/shepherd/dpo_utils.py`

PreferencePairBuilder **只产出 `reference_idx`**，不持有也不构建 reference cache。

**a) pair 元组格式**

```python

(winner_mol, loser_mol, winner_scores, loser_scores)
# 改为
(winner_mol, loser_mol, reference_idx, winner_scores, loser_scores)
```

`reference_idx` 从 `sample["source_mol_index"]` 获取（已有字段，无需新增）。

**b) pair_key 加入 reference identity**


同一对 winner/loser 在不同参考 NP 下是不同训练样本，不应被误去重。

### 2.4 `dpo_train.py` — 构建 reference cache + 适配 pair 格式

**文件**: `Shepherd/training/dpo_train.py`

`dpo_train.py` 是 reference_cache 的**唯一构建者和传递者**。

**a) 构建 reference cache**

```python
def build_reference_cache(molblocks_and_charges):
    """预处理参考分子：解析 mol、居中坐标、计算 radii/charges。"""
    cache = {}
    for idx, (molblock, charges) in enumerate(molblocks_and_charges):
        mol = Chem.MolFromMolBlock(molblock, removeHs=False)
        coords = np.array(mol.GetConformer().GetPositions())
        coords = coords - coords.mean(axis=0)
        mol = update_mol_coordinates(mol, coords)
        radii = get_atomic_vdw_radii(mol)
        if charges is None:
            # 复用 DPODataset._get_partial_charges 的 fallback 逻辑：
            # get_atomic_partial_charges → Gasteiger → zeros
            try:
                charges = get_atomic_partial_charges(mol)
            except Exception:
                try:
                    AllChem.ComputeGasteigerCharges(mol)
                    charges = np.array(
                        [atom.GetDoubleProp("_GasteigerCharge") for atom in mol.GetAtoms()],
                        dtype=float,
                    )
                    charges = np.nan_to_num(charges, nan=0.0)
                except Exception:
                    charges = np.zeros(mol.GetNumAtoms(), dtype=float)
        cache[idx] = {
            'mol': mol,
            'charges': charges,
            'radii': radii,
            'mol_coordinates': coords,
        }
    return cache
```

> 注意：charge fallback 逻辑与 `DPODataset._get_partial_charges()`（`dpo_dataset.py:135-148`）保持一致。可考虑提取为共享工具函数避免重复。

传入 `DPODataset` 初始化：

```python
reference_cache = build_reference_cache(reference_molblocks_and_charges)
dpo_dataset = DPODataset(
    preference_pairs=[],
    base_dataset=dataset,
    noise_schedule_dict=params["noise_schedules"],
    params=params,
    reference_cache=reference_cache,
)
```

**b) `sample_preference_pairs()`**

无需改签名。`evaluate_and_build_pairs()` 内部已有 `reference_idx = samples[0].get("source_mol_index", 0)`，只需把这个 idx 放进 pair 元组即可。

**c) `DPOSamplingCallback`**

已持有 `self.references`，不需要额外传递 cache。

### 2.5 standard loss — 第一阶段不改，第二阶段 ablation

**第一阶段（本次修复）**：
- DPO batch 的 standard denoising loss 保持现状（计算所有模态）
- 混合训练的真实数据 batch 正常计算全模态 loss
- 不改 `training_step()` 的 standard loss 逻辑

**第二阶段（ablation 实验）**：
- 测试 DPO batch 中只算 x1 standard loss（因为 x3/x4 来自参考 NP，去噪语义与预训练不一致）
- 测试结果决定是否保留

理由：当 x3/x4 来自参考 NP 而 x1 来自 winner 时，x3/x4 standard loss 变成"模型能否在 winner 的 x1 条件下去噪参考 NP 的表面"——预训练中从未出现的任务，可能产生噪声梯度。但这需要实验验证，不应在第一阶段引入额外变量。

### 2.6 `collate_dpo_batch()` — 无需改动

collate 逻辑不需要变——它只处理 batched `HeteroData`，内部 x3/x4 数据已在 `DPODataset.get()` 中通过 deepcopy 正确设置。`get()` 返回的 dict 格式与 `collate_dpo_batch()` 预期完全一致。

## 5. 风险

| 风险 | 缓解 |
|------|------|
| 移除 x4 DPO 信号后优化力度降低 | x1 DPO 信号在正确条件下更干净，应更有效 |
| x1 和 ref x3/x4 坐标系不对齐 | 保持与推理一致的 centering 约定（各自 COM），不额外对齐 |
| reference_cache 内存开销 | 每个参考分子 ~几十 KB，10 个参考 NP < 1 MB |
